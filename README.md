# ВОЛС — документирование PON-сетей

SaaS для операторов связи: учёт оптики на карте, включая трассы, кабели, муфты, сплиттеры, разварки, трассировку и оптический бюджет.

## Структура

```
apps/
  api/        Fastify + Drizzle ORM, PostgreSQL + PostGIS
  web/        React + Vite + Tailwind: карта сети (MapLibre GL + OSM) и справочник кабелей
packages/
  shared/     общие модели и расчёты для фронта и бэка: конструкция кабеля, цвета, оптика, пресеты справочников
infra/
  postgres/   init-скрипт docker: роль приложения vols_app
```

## Быстрый старт

Нужны Node.js 22+, pnpm 10 и Docker.

```bash
cp .env.example .env
```

```bash
pnpm install
```

```bash
pnpm db:up
```

```bash
pnpm db:migrate
```

```bash
pnpm db:seed
```

```bash
pnpm dev:api
```

```bash
pnpm dev:web
```

Веб открывается на http://localhost:5173 и проксирует `/api` на API.

Сид создаёт демо-оператора с фиксированным id `00000000-0000-4000-8000-00000000de00`, стартовыми справочниками и небольшой разваренной сетью. Авторизации пока нет. В режиме разработки оператор передаётся заголовком `X-Tenant-Id`, а веб по умолчанию работает от демо-оператора (сменить можно внизу бокового меню). При `NODE_ENV=production` такой доступ закрыт.

```bash
curl -H "X-Tenant-Id: <id>" http://localhost:3000/api/v1/cable-types
```

Тесты используют отдельную базу `vols_test`, которая пересоздаётся при каждом запуске. Нужен запущенный Postgres из docker compose.

```bash
pnpm test
```

## Карта (веб)

Карта открывается на `/map`. Режимы переключаются кнопками или клавишами V / P / R / C.

- **Выбор (V).** Клик по объекту открывает панель свойств. Если под курсором несколько линий (трасса и кабели), появляется меню выбора. Выбранное место можно перетащить: трассы и кабели потянутся следом, концы трасс привязаны к местам в БД.
- **Место (P).** Ставит опоры, колодцы, узлы и т.д. С галочкой «соединять трассой» каждая новая точка соединяется с предыдущей трассой выбранного вида, так улица опор рисуется подряд кликами. Клик по существующему месту продолжает цепочку от него, Esc её завершает.
- **Трасса (R).** Клик по месту начинает трассу, клики по карте добавляют изгибы, клик по другому месту её заканчивает. Backspace убирает изгиб. После каждого участка можно сразу рисовать следующий от конечного места.
- **Кабель (C).** Выбираете тип из справочника и кликаете по местам: путь между ними строится по трассам автоматически (кратчайший). Backspace — шаг назад. «Готово» или Enter открывает окно, где задаются название, статус, оборудование на концах и запасы.

Панели свойств:
- место: вид, статус, название, адрес, оборудование (муфты, ящики, кроссы, сплиттеры внутри корпусов, OLT), кабели, которые здесь заканчиваются или проходят;
- трасса: вид, статус, длина, концы, кабели на трассе;
- кабель: длина по трассам и с запасами, оборудование на концах.

Используемые объекты удалить нельзя, панель объясняет, что мешает.

Проектные объекты рисуются пунктиром или пустыми кружками, построенные — сплошными. Подложка и видимость слоёв переключаются в «Слоях». Источник подложки задаётся переменными `VITE_MAP_STYLE` и `VITE_SATELLITE_TILES` (см. `.env.example`). По умолчанию для разработки используются тайлы OSM.

## Разварка (веб)

Схема разварки открывается из панели места на карте: кнопка «Разварка» у муфты, абонентского ящика или кросса (`/equipment/:id/splicing`).

- **Раскладка схемы.** Приходящие кабели слева, уходящие справа (кнопка ⇄ переносит кабель на другую сторону). В центре — сплиттеры внутри корпуса и порты ящика или кросса: слева сторона под сварку, справа под патч-корд. Модули сворачиваются, у волокон цвета из справочника кабелей.
- **Соединение.** Кликните свободное волокно или порт, затем второе. По умолчанию это сварка, а для лицевой стороны адаптера и PON-порта — патч-корд. Клик по занятой точке или линии открывает карточку соединения: вид (сварка или механический сплайс), измеренные потери, кассета и место, удаление.
- **«Сварить по порядку».** Соединяет попарно волокна или порты: модуль в модуль, выходы сплиттера в волокна кабеля. Занятые точки пропускаются.
- **«Завести кабель».** Можно завести конец кабеля, лежащий в этом месте, или кабель, проходящий транзитом. Во втором случае пролёт разрезается в месте корпуса, все волокна идут транзитом (пунктир), а сварки на дальнем конце сохраняются. Кнопка ✂ у кабеля или модуля разрезает транзит, чтобы развести волокна.
- **Таблица соединений.** Список «откуда — куда» с цветами, видом, потерями и кассетами.

БД сама проверяет правила соединений, поэтому схема не даст:
- занять волокно дважды;
- сварить транзитное волокно;
- подключить патч-корд к стороне под сварку.

## Трассировка и оптический бюджет

Трассу можно построить из разных мест:
- панель места на карте: кнопки «PON 1…» у OLT, номера абонентских портов у ящика или кросса;
- карточка соединения в разварке: «Трассировать»;
- выбранная точка в разварке;
- ссылка `/map?trace=<id точки>`.

Как устроен обход (`POST /api/v1/trace`):
- Путь идёт от точки во все стороны через сварки, патч-корды, транзит, волокна, адаптеры и сплиттеры.
- Сплиттер направленный. Со входа путь расходится на все выходы, с выхода идёт только на вход, поэтому трасса от абонента не уходит в соседние выходы.
- На каждом шаге считаются потери на 1310, 1490 и 1550 нм и пройденная длина.
- Длина волокна — длина трасс пролёта плюс запасы (или измеренная длина пролёта). Затухание берётся из типа кабеля; для 1490 нм оно интерполируется между 1310 и 1550.
- Сварки и патч-корды считаются по измеренным потерям, а если их нет — по типовым: 0,05 и 0,3 дБ. Сплиттер — по номиналу модели, по каждому выходу (FBT) или по типовым значениям PLC.

Что показывает панель трассы:
- конечные точки (PON, ONU, абонентский порт, свободный выход сплиттера, неразваренное волокно);
- затухание до каждой точки и оценку по классу оптики (B+, C+, C++): запас до максимума, превышение бюджета или затухание ниже минимума (риск перегрузки ONU);
- путь до выбранной точки по шагам с накопленными потерями.

Трасса подсвечивается на карте.

Поиск места по рефлектометру (`POST /api/v1/trace/locate`): прибор подключён в начале трассы, вводится расстояние до события. Система идёт по пути до выбранной конечной точки, внутри пролёта учитывает участки трасс и запасы в местах, и ставит метку на карте с описанием «на трассе Оп. 1 → Оп. 2, 53 м от Оп. 1» или «в запасе кабеля в месте Оп. 2». Длина волокна в кабеле считается равной длине кабеля, коэффициент укрутки пока не учитывается.

## Документы (PDF)

PDF формируется на сервере через pdfmake со шрифтом Roboto (в нём есть кириллица). Браузер для этого не нужен. Скачать документы можно на странице «Документы» (`/documents`), паспорт — ещё и кнопкой «Паспорт PDF» в разварке.

- **Паспорт муфты, абонентского ящика или кросса** (`GET /api/v1/equipment/:id/passport.pdf`):
  - сведения о корпусе: модель, место, адрес, координаты, статус, сварок из ёмкости;
  - заведённые кабели с направлением, длиной пролёта и свободными волокнами;
  - сплиттеры: потери, куда подключён вход, занятые выходы;
  - соединения по кассетам: место в кассете, откуда и куда с цветами волокон, вид, измеренные или типовые потери;
  - транзитные волокна диапазонами и свободные волокна;
  - поля для подписей «Монтаж выполнил» и «Проверил».
- **Кабельный журнал** (`GET /api/v1/reports/cable-journal.pdf?status=built`):
  - все кабели оператора: начало и конец (место и оборудование), длина по трассе, запас, общая длина, занятые волокна, статус;
  - итоги по маркам.

## Справочник кабелей (веб)

- Список типов с поиском, фильтром по назначению, превью цветов модулей и отметкой «используется». Тип можно скопировать или удалить (если он не используется).
- Редактор типа:
  - основные параметры: название, назначение, тип волокна, затухание, диаметр;
  - конструкция по модулям: у каждого модуля свой цвет (из палитры или свой hex) с маркировкой и своё число волокон, 0 волокон означает заполнитель;
  - цвет каждого волокна выбирается отдельно;
  - модули можно переставлять, копировать и удалять;
  - «Заполнить по шаблону»: N модулей по M волокон, цвета из схем оператора;
  - сечение кабеля, которое обновляется на лету (клик по модулю выделяет его), и сквозная таблица волокон;
  - у используемого типа заблокированы модули и число волокон, менять можно только цвета и параметры;
  - при уходе со страницы без сохранения редактор предупреждает.

## Модель данных

Сеть разделена на три слоя. Физическая геометрия, кабели и логическая связность хранятся отдельно, поэтому трассировку и бюджет можно считать обходом графа.

### Инфраструктура

| Таблица | Что это |
|---|---|
| `sites` | Место на карте (Point): узел связи, опора, колодец, шкаф, здание, подъезд |
| `routes` | Участок трассы (LineString) между двумя местами: подвес, канализация, грунт, фасад. Длина считается в БД, концы линии сами «прилипают» к местам и двигаются вместе с ними |

### Справочники (свои у каждого оператора)

| Таблица | Что это |
|---|---|
| `cable_types` | Тип (марка) кабеля: конструкция, стандарт волокна, километровое затухание |
| `cable_type_modules` | Модули типа кабеля по порядку: у каждого свой цвет (с маркировкой) и своё число волокон. 0 волокон означает кордель-заполнитель |
| `cable_type_fibers` | Волокна типа кабеля: сквозной номер, модуль, позиция и собственный цвет |
| `color_schemes` | Цветовые схемы-шаблоны для быстрого заполнения конструкции (TIA-598, отечественная, дроп) |
| `equipment_models` | Модели муфт, ОРК, кроссов, сплиттеров, OLT, ONU |

Конструкция кабеля задаётся полностью вручную, а шаблон только помогает её заполнить. Тип хранит цвета копией, поэтому правка схемы не меняет существующие кабели. Целостность конструкции проверяется в БД в конце транзакции: модули идут подряд, число волокон совпадает, сквозная нумерация непрерывна. Если по типу уже проложены кабели, его конструкция заблокирована, а цвета менять можно.

### Кабели и оборудование

| Таблица | Что это |
|---|---|
| `cables` | Физический кабель (оболочка) определённого типа |
| `cable_spans` | Пролёт кабеля между точками разделки. Кабель, зашедший в муфту транзитом, состоит из двух пролётов |
| `span_routes` | Участки трассы, по которым идёт пролёт, по порядку |
| `cable_slacks` | Запасы (петли) кабеля в местах |
| `fibers` | Волокна пролёта. Создаются триггером по конструкции типа |
| `equipment` | Оборудование в месте. Может быть вложенным (сплиттер в муфте), вложенное всегда в том же месте, что и корпус. Порты создаются триггером по модели |

### Связность (граф)

| Таблица | Что это |
|---|---|
| `terminals` | Вершины графа. Это концы волокон (`fiber_end`, сторона `a` — в начале пролёта, `b` — в конце) и порты оборудования: вход и выход сплиттера, адаптер кросса или ОРК со сторонами `rear` (под сварку) и `front` (под патч-корд), PON-порт |
| `connections` | Рёбра: сварка, механический сплайс, патч-корд, транзит неразрезанного волокна |

Правила, которые проверяет БД:
- каждая точка участвует не больше чем в одном соединении;
- обе точки соединения находятся в месте соединения;
- сварка не делается на лицевую сторону адаптера и на PON-порт;
- патч-корд не подключается к стороне под сварку;
- транзит соединяет одно и то же волокно соседних пролётов одного кабеля;
- конец пролёта или корпус нельзя перенести, пока на нём остаются соединения.

Внутренние переходы для будущей трассировки: конец `a` ↔ конец `b` одного волокна, вход сплиттера ↔ все выходы, `rear` ↔ `front` одного адаптера.

### Мультиарендность и аудит

- Во всех таблицах оператора есть `tenant_id`, и на них включён принудительный RLS. Приложение работает под ролью `vols_app` без `BYPASSRLS`. Оператор задаётся на транзакцию в `withTenant()` (`apps/api/src/db/client.ts`).
- Все ссылки между объектами составные, `(tenant_id, id)`. Внешний ключ проверяется в обход RLS, поэтому без этого на чужой объект можно было бы сослаться, просто зная его uuid.
- Тест проверяет, что на каждой таблице с `tenant_id` включён RLS. Новая таблица без политики сломает тесты: её нужно добавить в список в миграции `0001_rls_triggers.sql`.
- `audit_log` пишется триггером. В журнал попадают старое и новое состояние строки и пользователь из `app.user_id`.

## Миграции

- `0000_init.sql` сгенерирована `drizzle-kit generate` из `apps/api/src/db/schema`.
- `0001_rls_triggers.sql` написана вручную: RLS, права, триггеры.

Когда меняется схема в TS, новую миграцию генерируют командой `pnpm db:generate`. Триггеры и политики для новых таблиц добавляются отдельной custom-миграцией (`drizzle-kit generate --custom`).
