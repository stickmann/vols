# Развёртывание на сервере с доменом

Пошаговые команды Docker без скриптов — в [DOCKER.md](DOCKER.md).

Стенд — три контейнера: PostgreSQL + PostGIS, API и Caddy. Caddy раздаёт веб, проксирует `/api` и сам выпускает и продлевает HTTPS-сертификат Let's Encrypt. Отдельно настраивать nginx и certbot не нужно.

На сервер ставятся **релизы GitHub**: опубликованный релиз — это тег на коммите в `main`, номер любой (`v0.42`, `v1.0`, `0.3`). Скрипты сами берут последний выпущенный релиз — по дате, а не по номеру, можно указать и конкретный. Код на сервере не меняется между релизами, а откат на прежнюю версию — одна команда.

Ниже пример с доменом `vols.example.ru` — подставьте свой.

## 0. Релиз на GitHub

Если релизов ещё нет, создайте первый: репозиторий → **Releases → Draft a new release** → **Choose a tag** → введите `v0.1.0` → **Create new tag on publish**, ветка `main` → **Generate release notes** → **Publish release**.

Дальнейшие версии — так же, из `main`. Номер выбирайте как удобно: последним считается выпущенный позже (например, `v0.5` после `v0.42` — новее). Теги с суффиксом (`v0.2.0-rc1`, `0.4-beta`) считаются предварительными: скрипты ставят их только если указать явно.

## 1. Сервер

- VPS с Ubuntu 22.04/24.04 или Debian 12, от 2 ГБ памяти и 20 ГБ диска.
- Если в сервисе будут данные абонентов операторов из РФ, сервер должен быть в РФ (152-ФЗ).
- Доступ по SSH под root (или пользователем с sudo).
- Порты 80 и 443 не заняты: на сервере не должно быть nginx/apache. Если в панели хостинга есть свой файрвол — откройте в нём 80 и 443 (TCP) и 443 (UDP).

## 2. DNS — сделайте заранее

В панели, где управляете доменом, создайте запись:

| Тип | Имя | Значение |
|---|---|---|
| A | `vols` (поддомен) или `@` (сам домен) | IP-адрес сервера |

Важно:
- **AAAA-запись** (IPv6) должна либо указывать на этот же сервер, либо отсутствовать. Чужая AAAA — самая частая причина, по которой сертификат не выпускается.
- **Cloudflare:** для этой записи выключите проксирование (серое облако, «DNS only»).
- Кириллический домен (`.рф`) указывайте скрипту в punycode, например `xn--80ak6aa92e.xn--p1ai`.

Запись расходится от нескольких минут до пары часов. Проверить с сервера:

```bash
getent hosts vols.example.ru
```

Должен вернуться IP сервера.

## 3. Доступ сервера к репозиторию

Репозиторий приватный, поэтому серверу нужен ключ только на чтение (deploy key). На сервере:

```bash
ssh-keygen -t ed25519 -N "" -f ~/.ssh/id_ed25519 -C vols-server
```

```bash
cat ~/.ssh/id_ed25519.pub
```

Скопируйте выведенную строку на GitHub: репозиторий → **Settings → Deploy keys → Add deploy key**. Галочку «Allow write access» не ставьте.

## 4. Установка

```bash
git clone git@github.com:stickmann/vols.git
```

На вопрос о подлинности github.com ответьте `yes`.

```bash
cd vols
```

```bash
./deploy/install.sh vols.example.ru
```

Скрипт:
1. скачивает список релизов и переключается на последний;
2. проверяет, что домен указывает на этот сервер, нет чужой AAAA-записи и свободны порты 80/443; открывает их в ufw, если он включён;
3. ставит Docker, если его нет;
4. спрашивает логин и пароль для входа на сайт;
5. генерирует пароли БД и сохраняет настройки в `.env.prod` (файл секретный, доступен только root);
6. собирает и запускает контейнеры — первый раз 3–10 минут;
7. применяет миграции и создаёт демо-оператора с демо-сетью.

Конкретный релиз вместо последнего:

```bash
./deploy/install.sh vols.example.ru --version v0.1.0
```

После этого откройте `https://vols.example.ru/`, введите логин и пароль, заданные при установке. Номер версии виден внизу бокового меню и в `https://vols.example.ru/health`. При первом заходе Caddy получает сертификат — первая загрузка может занять до минуты.

Если раньше ставили по IP без домена — просто запустите `./deploy/install.sh vols.example.ru` ещё раз: он сменит адрес сайта, данные сохранятся.

## Обновление и откат

Опубликуйте новый релиз на GitHub, затем на сервере:

```bash
./deploy/update.sh
```

Скрипт делает резервную копию базы, переключается на последний релиз, пересобирает контейнеры и применяет миграции. Данные сохраняются.

Перейти на конкретную версию, в том числе откатиться на прежнюю:

```bash
./deploy/update.sh v0.1.0
```

При откате скрипт спросит подтверждение: миграции базы не откатываются, и если более новая версия меняла схему, старый код может с ней не работать. Тогда восстановите копию, сделанную перед обновлением (см. «Обслуживание»).

Проверить неопубликованный код из `main` до релиза: `./deploy/update.sh main`. Вернуться на релиз — `./deploy/update.sh`.

Не правьте файлы проекта на сервере: скрипт откажется переключать версию. Все настройки — в `.env.prod`, он в репозиторий не попадает.

## Сервер, где 80/443 уже заняты

Если на сервере уже работает другой веб-сервер, ВОЛС не нужно ставить вместо него. Тот веб-сервер остаётся снаружи, принимает HTTPS и выпускает сертификат и для домена ВОЛС, а запросы передаёт ВОЛС. Наружу ВОЛС тогда портов не открывает. `install.sh` сам обнаружит занятые порты и подскажет команду.

### Соседний node-checker (Caddy в Docker)

Пример для домена `vols.ctrlvpn.ru` и node-checker в `~/node-checker`. Сначала A-запись домена на IP сервера, затем:

```bash
./deploy/install.sh vols.ctrlvpn.ru --behind-proxy node-checker_default
```

ВОЛС соберётся и подключится к сети Docker `node-checker_default` под именем `vols-web`.

```bash
./deploy/attach-node-checker.sh ~/node-checker
```

Скрипт добавляет в Caddy node-checker сайт `vols.ctrlvpn.ru → vols-web:80`:
- в `deploy/Caddyfile` node-checker — подключение файлов `deploy/sites/*.caddy`;
- в его `docker-compose.caddy.yml` — монтирование папки `deploy/sites`;
- файл `deploy/sites/vols.caddy` с доменом ВОЛС.

Перед применением скрипт проверяет конфиг Caddy и при ошибке всё откатывает. Затем пересоздаёт контейнер `node-checker-caddy` — сайт node-checker недоступен несколько секунд. Сертификат для домена ВОЛС Caddy выпустит при первом заходе.

Скрипт меняет отслеживаемые git файлы node-checker. Закоммитьте эти правки в репозиторий node-checker, чтобы `git pull` там не конфликтовал. Повторный запуск скрипта ничего не дублирует.

Проверка ВОЛС в обход Caddy, прямо с сервера:

```bash
curl -I http://127.0.0.1:8090/
```

Ответ `401 Unauthorized` — нормально: это запрос пароля входа.

Обновления (`./deploy/update.sh`) и копии (`./deploy/backup.sh`) работают как обычно: режим сохранён в `.env.prod` (`EDGE_NETWORK`).

### Другой веб-сервер

- **Caddy или nginx в Docker:** узнайте его сеть (`docker inspect -f '{{range $k, $v := .NetworkSettings.Networks}}{{$k}} {{end}}' ИМЯ_КОНТЕЙНЕРА`), установите с `--behind-proxy ЭТА_СЕТЬ` и добавьте в его конфиг проксирование домена на `vols-web:80`. Для nginx — `proxy_pass http://vols-web:80;` с заголовками `Host` и `X-Forwarded-*`.
- **nginx прямо на сервере (не в Docker):** создайте сеть `docker network create vols-edge` и установите с `--behind-proxy vols-edge`, а в nginx — `proxy_pass http://127.0.0.1:8090;`. Сертификат для домена — через certbot.

## Если что-то не работает

| Признак | Что проверить |
|---|---|
| Браузер пишет про небезопасное соединение или сайт не открывается | Логи Caddy: `docker compose --env-file .env.prod -f docker-compose.prod.yml logs web`. Строки с `acme`/`challenge` — проблема с DNS (A/AAAA-запись, Cloudflare) или закрытым портом 80 в файрволе хостинга. |
| Сайт открылся, но карта или данные не грузятся | `docker compose --env-file .env.prod -f docker-compose.prod.yml logs api` |
| Контейнер перезапускается | `docker compose --env-file .env.prod -f docker-compose.prod.yml ps` |

Let's Encrypt ограничивает число неудачных попыток (5 в час на домен). Если сертификат не выпускается — сначала исправьте DNS, потом перезапустите: `docker compose --env-file .env.prod -f docker-compose.prod.yml restart web`.

## Пока нет входа в систему

Весь сайт закрыт логином и паролем на уровне Caddy (basic auth). Внутри работает режим просмотра: `ALLOW_TENANT_HEADER=true`, оператор выбирается в интерфейсе, по умолчанию — демо-оператор. Не вносите реальные данные абонентов, пока не готов полноценный вход с ролями.

## Обслуживание

| Задача | Команда |
|---|---|
| Обновить до последнего релиза | `./deploy/update.sh` |
| Перейти на версию / откатиться | `./deploy/update.sh v0.1.0` |
| Какая версия развёрнута | `git describe --tags --always` |
| Резервная копия базы | `./deploy/backup.sh` |
| Логи | `docker compose --env-file .env.prod -f docker-compose.prod.yml logs -f api web` |
| Состояние | `docker compose --env-file .env.prod -f docker-compose.prod.yml ps` |

Ежедневная копия по расписанию (в 03:15):

```bash
(crontab -l 2>/dev/null; echo "15 3 * * * cd $PWD && ./deploy/backup.sh >> /var/log/vols-backup.log 2>&1") | crontab -
```

Восстановление из копии — по шагам в [DOCKER.md](DOCKER.md#восстановление-из-копии).

Смена пароля входа на сайт: получите новый хэш, замените им значение `BASIC_AUTH_HASH` в `.env.prod` (в одинарных кавычках) и примените `docker compose --env-file .env.prod -f docker-compose.prod.yml up -d web`.

```bash
docker run --rm caddy:2.10-alpine caddy hash-password --plaintext 'новый-пароль'
```

## Подложка карты

По умолчанию используются тайлы tile.openstreetmap.org. Для показа это нормально, но для рабочего сервиса их правила такую нагрузку не допускают. Свой стиль и спутник задаются переменными `VITE_MAP_STYLE` и `VITE_SATELLITE_TILES` в `.env.prod`. Они попадают в сборку, поэтому после изменения пересоберите текущую версию: `./deploy/update.sh $(git describe --tags --always)`.
