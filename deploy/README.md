# Развёртывание на сервере с доменом

Стенд — три контейнера: PostgreSQL + PostGIS, API и Caddy. Caddy раздаёт веб, проксирует `/api` и сам выпускает и продлевает HTTPS-сертификат Let's Encrypt. Отдельно настраивать nginx и certbot не нужно.

Ниже пример с доменом `vols.example.ru` — подставьте свой.

## 1. Сервер

- VPS с Ubuntu 22.04/24.04 или Debian 12, от 2 ГБ памяти и 20 ГБ диска.
- Если в сервисе будут данные абонентов операторов из РФ, сервер должен быть в РФ (152-ФЗ).
- Доступ по SSH под root (или пользователем с sudo).
- Порты 80 и 443 не заняты: на сервере не должно быть nginx/apache. Если в панели хостинга есть свой файрвол — откройте в нём 80 и 443 (TCP) и 443 (UDP).

## 2. DNS — сделайте заранее

В панели, где управляете доменом, создайте запись:

| Тип | Имя | Значение |
|---|---|---|
| A | `vols` (поддомен) или `@` (сам домен) | IP-адрес сервера |

Важно:
- **AAAA-запись** (IPv6) должна либо указывать на этот же сервер, либо отсутствовать. Чужая AAAA — самая частая причина, по которой сертификат не выпускается.
- **Cloudflare:** для этой записи выключите проксирование (серое облако, «DNS only»).
- Кириллический домен (`.рф`) указывайте скрипту в punycode, например `xn--80ak6aa92e.xn--p1ai`.

Запись расходится от нескольких минут до пары часов. Проверить с сервера:

```bash
getent hosts vols.example.ru
```

Должен вернуться IP сервера.

## 3. Доступ сервера к репозиторию

Репозиторий приватный, поэтому серверу нужен ключ только на чтение (deploy key). На сервере:

```bash
ssh-keygen -t ed25519 -N "" -f ~/.ssh/id_ed25519 -C vols-server
```

```bash
cat ~/.ssh/id_ed25519.pub
```

Скопируйте выведенную строку на GitHub: репозиторий → **Settings → Deploy keys → Add deploy key**. Галочку «Allow write access» не ставьте.

## 4. Установка

```bash
git clone git@github.com:stickmann/vols.git
```

На вопрос о подлинности github.com ответьте `yes`.

```bash
cd vols
```

```bash
./deploy/install.sh vols.example.ru
```

Скрипт:
1. проверяет, что домен указывает на этот сервер, нет чужой AAAA-записи и свободны порты 80/443; открывает их в ufw, если он включён;
2. ставит Docker, если его нет;
3. спрашивает логин и пароль для входа на сайт;
4. генерирует пароли БД и сохраняет настройки в `.env.prod` (файл секретный, доступен только root);
5. собирает и запускает контейнеры — первый раз 3–10 минут;
6. применяет миграции и создаёт демо-оператора с демо-сетью.

После этого откройте `https://vols.example.ru/`, введите логин и пароль из шага 3. При первом заходе Caddy получает сертификат — первая загрузка может занять до минуты.

Если раньше ставили по IP без домена — просто запустите `./deploy/install.sh vols.example.ru` ещё раз: он сменит адрес сайта, данные сохранятся.

## Если что-то не работает

| Признак | Что проверить |
|---|---|
| Браузер пишет про небезопасное соединение или сайт не открывается | Логи Caddy: `docker compose --env-file .env.prod -f docker-compose.prod.yml logs web`. Строки с `acme`/`challenge` — проблема с DNS (A/AAAA-запись, Cloudflare) или закрытым портом 80 в файрволе хостинга. |
| Сайт открылся, но карта или данные не грузятся | `docker compose --env-file .env.prod -f docker-compose.prod.yml logs api` |
| Контейнер перезапускается | `docker compose --env-file .env.prod -f docker-compose.prod.yml ps` |

Let's Encrypt ограничивает число неудачных попыток (5 в час на домен). Если сертификат не выпускается — сначала исправьте DNS, потом перезапустите: `docker compose --env-file .env.prod -f docker-compose.prod.yml restart web`.

## Пока нет входа в систему

Весь сайт закрыт логином и паролем на уровне Caddy (basic auth). Внутри работает режим просмотра: `ALLOW_TENANT_HEADER=true`, оператор выбирается в интерфейсе, по умолчанию — демо-оператор. Не вносите реальные данные абонентов, пока не готов полноценный вход с ролями.

## Обслуживание

| Задача | Команда |
|---|---|
| Обновить код и применить миграции | `./deploy/update.sh` |
| Резервная копия базы | `./deploy/backup.sh` |
| Логи | `docker compose --env-file .env.prod -f docker-compose.prod.yml logs -f api web` |
| Состояние | `docker compose --env-file .env.prod -f docker-compose.prod.yml ps` |

Ежедневная копия по расписанию (в 03:15):

```bash
(crontab -l 2>/dev/null; echo "15 3 * * * cd $PWD && ./deploy/backup.sh >> /var/log/vols-backup.log 2>&1") | crontab -
```

Восстановление из копии:

```bash
gunzip -c backups/vols-ДАТА.sql.gz | docker compose --env-file .env.prod -f docker-compose.prod.yml exec -T db psql -U vols -d vols
```

Смена пароля входа на сайт: получите новый хэш, замените им значение `BASIC_AUTH_HASH` в `.env.prod` (в одинарных кавычках) и примените `docker compose --env-file .env.prod -f docker-compose.prod.yml up -d web`.

```bash
docker run --rm caddy:2.10-alpine caddy hash-password --plaintext 'новый-пароль'
```

## Подложка карты

По умолчанию используются тайлы tile.openstreetmap.org. Для показа это нормально, но для рабочего сервиса их правила такую нагрузку не допускают. Свой стиль и спутник задаются переменными `VITE_MAP_STYLE` и `VITE_SATELLITE_TILES` в `.env.prod`, после чего нужно запустить `./deploy/update.sh`.
